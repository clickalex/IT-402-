Chapter 8: DBMS Introduction

🎯 Marks lens: Definitions of database, DBMS, table, field, record and database advantages.

📖 Concepts explained simply

A database is an organised collection of related data. A DBMS provides tools to define structures, enter records, search, update and produce outputs. A table stores one subject; a field is an attribute/column; a record is one complete row. A primary key uniquely identifies a record.

Compared with a scattered spreadsheet, a database reduces unnecessary duplication and can control relationships, validation and access. Good design begins by understanding entities and their attributes.

Term / featureMeaningExample
DatabaseRelated organised dataSchool records
TableCollection of same-type recordsStudent
RecordOne complete rowOne student
Real-life example: A library stores each member once and connects loans to members and books instead of repeating names on every slip.

🖱️ Exact LibreOffice procedure

  1. File → New → Database; choose Create a new database and Finish.
  2. Save the .odb file in the Base folder and use a meaningful name.
  3. Identify entities, fields and a likely primary key before creating tables.
  4. Use the Tables, Queries, Forms and Reports panels for the appropriate task.

Useful keys: Ctrl+S saves the .odb; F4 refreshes some database views.

🧠 Memory trick: Fields are facts; records are rows; tables collect records.
⚠️ Common mistakes: Calling a row a field; storing every fact in one giant table; confusing an .odb database with a table.

❓ One-mark questions

What is a DBMS?
Software used to create, store, retrieve, update and manage database data.

LibreOffice Base.

It improves consistency, accuracy or efficiency.

Check the result, save a version and protect private information.

Correct terminology plus an application example.

Two-mark questions

Give two database advantages.
Reduced duplication and faster searching; validation and controlled reports are also benefits.
Field versus record?
A field is a column attribute; a record is one complete row.
Why plan tables first?
Good design prevents repeated data, ambiguous fields and difficult relationships.

Four-mark model answer

Explain how a DBMS differs from a simple paper register.
A DBMS stores related data in structured tables, identifies records, validates entries and can retrieve selected information through queries. It can also provide forms for entry and reports for presentation. A paper register lacks these automated controls.

Chapter 9: Base Tables

🎯 Marks lens: Design View, field types, primary keys, AutoValue and validation are central practical skills.

📖 Concepts explained simply

Table Design View defines the structure before data entry. A field name should be clear and a field type should match the data: Text for names, Integer for counts or IDs, Date for dates and Decimal for money. A primary key must be unique and not empty. AutoValue can generate an ID.

Term / featureMeaningExample
StudentIDInteger, primary key, AutoValue101
NameTextRiya Singh
DOBDate2010-08-16
FeePaidDecimal/Currency450.00
Real-life example: A Student table uses StudentID rather than student name as the identifier because two students may share a name.

🖱️ Exact LibreOffice procedure

  1. Tables → Create Table in Design View.
  2. Enter Field Name and Field Type; add a description where useful.
  3. Right-click the ID row → Primary Key; set AutoValue to Yes for generated IDs.
  4. Save, switch to table view, enter five test records and check types and required values.

Useful keys: Use Tab to move between design columns; Ctrl+S saves.

🧠 Memory trick: ID identifies; type validates; table stores.
⚠️ Common mistakes: Using Text for every field; duplicate primary keys; mixing date formats; putting multiple values in one field.

❓ One-mark questions

What is a primary key?
A field or combination of fields that uniquely identifies each record.
Give one use of a primary key.
StudentID.
What is one benefit?
It improves consistency, accuracy or efficiency.
Name one precaution.
Check the result, save a version and protect private information.
Which skill does this test?
Correct terminology plus an application example.

Two-mark questions

Why not use Name as primary key?
Names may repeat, change or contain spelling variations.
Give two suitable field types.
Date for dates and Integer for counts/IDs; Text for names and Decimal for money.
What is AutoValue?
A setting that generates a new numeric identifier for each record.

Four-mark model answer

Explain the design of a Student table.
Create fields StudentID, Name, Class, DOB and FeePaid. Choose matching types, make StudentID the AutoValue primary key, save the table and test records. Inspect invalid input rather than silently storing it.

Chapter 10: Relationships

🎯 Marks lens: Primary/foreign keys, one-to-many relationships and referential integrity are high-value topics.

📖 Concepts explained simply

A relationship connects matching fields in tables. The parent table contains a unique primary key; the child table contains a foreign key that may repeat. In a one-to-many relationship one student can have many loans, but each loan belongs to one student. Referential integrity helps prevent a child record pointing to a missing parent.

Term / featureMeaningExample
Parent PKUnique identifierStudent.StudentID
Child FKReference that may repeatLoan.StudentID
CardinalityHow many records relateOne-to-many
Real-life example: A student’s name is stored once in Student; Loan stores StudentID for every borrowed book.

🖱️ Exact LibreOffice procedure

  1. Create and save parent and child tables with compatible key types.
  2. Tools → Relationships; add the required tables.
  3. Drag the parent primary-key field onto the matching child foreign-key field.
  4. Enable referential integrity where suitable, save the layout and test a valid and invalid child record.

Useful keys: Use clear PK/FK names; Ctrl+S saves relationship design.

🧠 Memory trick: One parent, many children; PK to FK.
⚠️ Common mistakes: Joining fields of different types; duplicating parent rows; deleting a parent without considering child records.

❓ One-mark questions

What is a foreign key?
A field in a child table that refers to a primary key in a parent table.
Give one use of a foreign key.
Loan.StudentID refers to Student.StudentID.
What is one benefit?
It improves consistency, accuracy or efficiency.
Name one precaution.
Check the result, save a version and protect private information.
Which skill does this test?
Correct terminology plus an application example.

Two-mark questions

What is one-to-many?
One parent record can relate to many child records, while each child has one parent.
Why use relationships?
They reduce repeated data and maintain meaningful connections.
What is referential integrity?
Rules that help ensure a foreign key refers to an existing parent record.

Four-mark model answer

Explain how to create and test a relationship.
Create compatible primary and foreign key fields, open Tools → Relationships, drag the parent key to the child key and save. Test a valid child record and then an invalid ID to understand the integrity rule.

Chapter 11: Queries

🎯 Marks lens: Criteria, sorting, calculated fields and query output are important.

📖 Concepts explained simply

A query is a saved question. It retrieves selected fields and records from one or more tables without creating a second source of truth. Criteria can match text, numbers or dates. Sorting changes presentation order. A query can include a calculated field such as FeePaid + Fine.

Term / featureMeaningExample
Field rowColumns to display or filterName, FeePaid
CriteriaCondition for matching records< 500
SortOrder of resultsName ascending
Real-life example: “Find unpaid students in Class 10A” is a query with a Class criterion and a FeePaid condition, not a manual scan.

🖱️ Exact LibreOffice procedure

  1. Queries → Create Query in Design View; add related tables.
  2. Double-click required fields; enter criteria such as 10A or <500.
  3. Choose Sort Ascending/Descending and run the query to inspect results.
  4. Save with a descriptive name such as Unpaid_Class10A and do not edit source data accidentally.

Useful keys: Use quotes carefully for text criteria; Ctrl+S saves the query.

🧠 Memory trick: Question → criteria → result.
⚠️ Common mistakes: Writing criteria as a sentence; selecting unrelated tables; confusing query results with editable source data.

❓ One-mark questions

What is a query?
A saved instruction that retrieves records meeting specified conditions.
Give one use of a query.
Students with FeePaid less than 500.
What is one benefit?
It improves consistency, accuracy or efficiency.
Name one precaution.
Check the result, save a version and protect private information.
Which skill does this test?
Correct terminology plus an application example.

Two-mark questions

Query versus table?
A table stores source records; a query retrieves a selected view of those records.
What is criteria?
A condition that decides which records appear in a query result.
Why sort a query?
To make results easier to read, compare or report.

Four-mark model answer

Describe a query to find students with unpaid fees.
Open Query Design, add Student, select Name, Class and FeePaid, enter the correct FeePaid criterion, sort by Name, run and inspect. Save it descriptively and correct the source table if the output reveals a data error.

Chapter 12: Forms and Reports

🎯 Marks lens: Forms simplify data entry; reports present grouped, printable output.

📖 Concepts explained simply

A form is an interface for entering or viewing records. It can provide labels, controls and navigation so users do not edit a complex table directly. A report is formatted output for reading, grouping, totals or printing. It should be generated from reliable tables or queries and previewed before export.

Term / featureMeaningExample
FormEnter/view recordsStudent entry screen
ReportPresent analysed outputStudents by Class
WizardGuided creation stepsSelect fields and layout
Real-life example: A receptionist enters visitors through a form; a manager prints a daily report grouped by department.

🖱️ Exact LibreOffice procedure

  1. Forms → Use Wizard to Create Form; select table and fields.
  2. Choose layout and data-entry options, then Finish and test three records.
  3. Reports → Use Wizard; select fields, grouping and sort order.
  4. Preview, save with meaningful names and File → Export as PDF.

Useful keys: Ctrl+P prints after preview; Ctrl+S saves.

🧠 Memory trick: Forms feed; reports read.
⚠️ Common mistakes: Treating a report as the source table; unlabeled controls; printing without preview; including unnecessary private fields.

❓ One-mark questions

What is a form?
A user-friendly interface for entering or viewing database records.
Give one use of a form.
StudentEntry form.
What is one benefit?
It improves consistency, accuracy or efficiency.
Name one precaution.
Check the result, save a version and protect private information.
Which skill does this test?
Correct terminology plus an application example.

Two-mark questions

Form versus report?
A form is mainly for entry/viewing; a report is formatted output for reading or printing.
Why use a query as report source?
It supplies only the required records and fields, possibly filtered or sorted.
Give two report checks.
Preview layout and totals; check headings, grouping, page breaks and private fields.

Four-mark model answer

Compare forms and reports and explain their workflow.
A form is designed for controlled entry and viewing, so it uses labels and navigation. A report is designed for communication, so it uses grouping, sorting, headings and print layout. Create and test the form first, then generate the report from a table or query, preview and export it.
